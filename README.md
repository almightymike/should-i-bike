# Should I Bike?

Three-day ride outlook. On first visit, Cloudflare estimates the visitor's city from their IP address without a device-location permission prompt. If no estimate is available, the dashboard uses Miramar, Wellington. A manually selected location takes priority on later visits to the same browser. The page shows best overall, best backup, weakest option, three day cards with four-hour ride windows, and a final call. It shows live conditions and a simple rating based on wind, gusts, rain probability, predicted rain and thunderstorms.

## Run locally

Open `index.html` in a browser. No build step or dependencies are needed. The browser must be able to reach the Open-Meteo forecast and geocoding APIs.

## Deploy to Cloudflare Pages

Connect this GitHub repository to Cloudflare Pages. Set the production branch to `main`, choose no framework preset, use `exit 0` as the build command, and use `.` as the build output directory. The site will publish after the pull request is merged into `main`. The build command is recommended by Cloudflare for static sites using Pages Functions.

The `/api/location` Pages Function reads Cloudflare's approximate IP location and returns only a city, region, country code, coordinates and timezone with `Cache-Control: private, no-store`. It does not return the IP address. `_routes.json` limits Function invocations to that route. If it returns no usable coordinates, the page uses Miramar. Test the endpoint on the deployed domain: `/api/location` should return a small JSON object or an empty 204 response, rather than 404. Approximate IP location can be wrong for VPN and mobile-network users. Manual location search is always available; **Use approximate location** clears a saved manual choice and detects again.

The deployed site uses Cloudflare Access. Keep the production `pages.dev` address and preview addresses covered by separate Access applications. The GitHub repository is public, so do not commit private data or API keys.

If the live site shows an older version after a merge, open the Pages project's Deployments tab and compare the Production deployment commit with GitHub `main`. Retrying an old deployment republishes that old commit. Check Settings > Builds for the connected repository, production branch and automatic deployments, then check the Cloudflare Workers and Pages GitHub app's repository access before triggering a fresh commit on `main`.

## Forecast logic

- Miramar fallback data comes from Open-Meteo at approximately 41.317° S, 174.817° E. Search locations come from Open-Meteo's GeoNames-based geocoding service. Each forecast uses local time at the chosen location. Suggestions appear after three typed characters; keyboard arrows and Enter also select a result.
- Location search sits above two ride-preference switches. **Avoid rain** starts on for a new visitor and remembers the visitor's choice on that device. With it on, Best and Backup require every hourly rain chance in the two-hour ride to be below 20% and predicted rain across the ride to be below 0.1 mm. Turning it off lets light rain qualify; predicted heavy rain and thunderstorms still affect ratings. Both switches update the displayed forecast and highlights using the loaded weather data.
- By default, early morning covers 05:00–08:59, late morning 09:00–12:59, afternoon 13:00–16:59, and evening 17:00–20:59. An unchecked-by-default **Include late-night rides** switch adds 21:00–23:59 to the forecast and ride recommendations for this page load. It resets to off on a new load. Passed hours are not rated. Once no two full future forecast hours remain (from 19:00 normally or 22:00 with late night enabled), the dashboard shows the next three days.
- Forecast day cards show the rating and conditions for each full time window without a departure time. Best overall and Best backup cards show the highest-scoring two-hour ride-out stretches, their exact time ranges, and temperature, wind, gusts, rain chance and rain total for those two hours. A two-hour ride can still be recommended at 5–9°C with a comfort penalty. A stretch below 5°C is not selected for Best overall or Best backup. The Weakest option shows the poorest two-hour stretch for comparison, not a departure recommendation.
- Each card displays the lowest and highest hourly temperature across its own time range, plus a short comfort tip. Each window also displays the maximum hourly wind, gust and rain probability, and the sum of predicted hourly rain.
- Best and Backup highlights add one clothing tip for their two-hour forecast. Cold rides suggest layers and gloves; a windy dry ride suggests a gilet; possible showers suggest a packable rain jacket; predicted rain of at least 0.4 mm suggests a waterproof jacket. Rain jackets replace, rather than stack with, gilet advice. In warm weather the tip suggests breathable kit, with separate hydration and heat advice. The Weakest comparison does not suggest clothing for a ride.
- With **Avoid rain** on, Favourable means wind below 20 km/h, gusts below 35 km/h, rain chance below 20%, and predicted rain below 0.1 mm. At 20% or more, or 0.1 mm or more, the window is Use caution and its two-hour stretch cannot be selected as Best or Backup. The 15% boundary for a 5/5 score still distinguishes 13% from 17% when other conditions are ideal. These percentages are personal preferences, not cycling safety standards.
- With **Avoid rain** off, rain probability alone does not lower the rating or score. Predicted rain of at least 0.4 mm marks Use caution and 1.5 mm marks Avoid. Wind at least 30 km/h, gusts at least 60 km/h, or forecast thunder marks Avoid in either mode. Gusts of 50–59 km/h with otherwise manageable weather are a conditional orange 2/5. A prominent warning says to avoid open coasts, ridges and bridges and only consider a genuinely sheltered local route. No specific route is assumed safe from a point forecast.
- Scores split ratings into five planning bands: 5/5 requires wind below 15 km/h and gusts below 25 km/h, plus rain chance below 15% and rain below 0.1 mm with Avoid rain on, or rain below 0.4 mm with it off. Otherwise Favourable is 4/5. Use caution is 3/5 when wind is below 25 km/h, gusts below 42 km/h, and predicted rain below 0.8 mm; with Avoid rain on, rain chance must also stay below 45%. Otherwise it is 2/5. Avoid is always 1/5. A temperature of 15–22°C does not lower the weather score. A low below 15°C or high of 23–26°C caps the score at 4; a low of 5–9°C caps it at 3 and marks Use caution; a low below 5°C or a high of at least 27°C caps it at 2 and marks Use caution. Severe wind, heavy rain or thunder still make the rating Avoid regardless of temperature.
- Best and backup are chosen from the highest-scoring suitable two-hour stretches in different complete upcoming windows. Within a score band, the lower combined wind, gust and rain burden wins. A good two-hour stretch may appear inside a lower-rated full window because conditions change during the window. Weakest is the lowest-ranked two-hour stretch across complete windows. If no two-hour stretch meets the weather and temperature limits, the page recommends no ride.
- The browser checks for a new local forecast hour while the tab is visible and reloads the forecast when the hour changes. It also checks when the tab becomes visible again. This removes departure windows that have already begun without requiring a manual refresh.
- These thresholds are personal planning heuristics, not official safety limits. Route notes compare broad exposure and are not navigation instructions.
- Miramar and Wellington city have broad local route examples. For other locations, notes use wind direction and the rating to suggest a sensible loop strategy. The forecast API does not know local roads, so it does not name unverified routes elsewhere.
- The page never shows a ride rating when required forecast inputs are missing. It displays `/inco` and states what is missing.

Forecast data is from [Open-Meteo](https://open-meteo.com/) under CC BY 4.0. The free API is intended for non-commercial use.
